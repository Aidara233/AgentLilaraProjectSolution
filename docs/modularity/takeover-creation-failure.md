# 接管后创建失败的阶段边界审计

本文为源码只读审计与实现方案，尚未实现回滚或执行故障注入。当前 claim/成员索引原子更新已存在，但不构成创建事务。禁止用包住 CreateSession 的广义 catch 恢复旧占用。

## 已确认的发布顺序

1. compact 调 TakeOverSessionPool，升级调 TakeOverChannelPool，池活跃 id 和新成员索引先发布；新 RuntimeSession 尚不存在。升级忽略 TakeOverChannelPool 的 false 返回，需单独决定失败语义。
2. CreateSession 读取类型配置、计算组件清单、构造会话并注入操作。InitializeGraphMount 绑定的是惰性 provider，绑定本身不实例化图。随后读取 Mind.Resurrector 并 Attach：即使尚未进入会话表，也可能已经产生外部完成事件订阅。
3. InitComponents 在 try/catch 内执行，但组件可能先初始化部分外部资源再抛错；异常被记日志后继续创建。不能把这个过程认作没有副作用的准备阶段。
4. `_sessions[session.SessionId] = session` 是会话表发布点，发生在 ConfigureCores 之前。ConfigureCores、GetActiveEnginesSnapshot、端口遍历/Subscribe/AddInputPort 与 AutoClaim 不在统一 catch 内。配置构造、提示词读取、非法集合输入等均可能同步失败；已发布对象和已订阅端口可能仍保留。
5. Subscribe 立即把新端口加入 MessageEngine 订阅表；AutoClaim 立即修改池/频道占用并同步连接状态。这是外部资源发布，与后台是否启动无关。
6. 上下文宿主、Bootstrap、spec 写入分别捕获异常并降级继续。Bootstrap 可执行工具及外部动作，捕获错误不撤销已经发生的动作；spec 写入失败也不表示创建失败。
7. InitCompression 无外层降级 catch，之后 Task.Run 排队启动后台 RunAsync。后台 catch 记录崩溃，finally 释放当前活跃 Full claim；这不是恢复旧会话的补偿。后台可能在 CreateSession 返回前已经运行或结束。
8. Task.Run 之后还可能 CreateSubPool，然后 CreateSession 返回。compact 返回后 SetActiveCore 可能构造另一个核心并抛错，轮次继承、子存档改写和资源回调都已处于后台可能运行的阶段。子存档改写逐项吞错；资源注册表逐回调捕获异常，某些资源可能已经 rebind。升级在返回前还记录日志。

## 回滚判据

必须分别记录池预定、会话表发布、外部资源发布、后台排队四种状态。没有后台任务只说明最后一步未发生，不说明可以撤回占用。当前代码的组件初始化早于会话表发布，因此仅检查 `_sessions.ContainsKey(newId)` 也不足以证明未发布。

仅允许条件撤销完全未发布的新预定：池对象仍是票据中的对象，活跃 id 仍为票据 newId，newId 索引仍指向该池，新旧对象未被其他接管替换，且组件/订阅/资源回调尚未开始或已经由明确的逐项补偿完成。否则必须保留新状态并报告阶段失败，交给后续终止/清理流程，不能重新赋旧 claim。

已进入会话表或外部发布阶段：本切片不自动回滚。未来若要支持，需要拥有会话表、订阅、图实例、组件、持久化和资源 rebind 的独立创建事务，并证明所有补偿幂等。已排队后台或 compact 后处理异常：绝不把池恢复为旧占用。

## 最小实现方案

- 引入接管预定票据，保存 pool 引用、oldActiveId/newId、newId 原先是否在 Members/成员索引，以及单调创建阶段。票据在 `_poolLock` 内产生；释放旧占用不能绕过票据的条件检查。
- 把类型配置、最终组件清单和不执行外部代码的 spec 构造移到预定之前。可抛错的核心配置准备若要提前执行，必须先明确它的文件/缓存副作用，不把它简单标成纯函数。
- 给创建协调器显式阶段回调，发布点之前更新阶段；阶段不允许因异常倒退。组件初始化开始即越过“可以直接撤销预定”的边界。票据结束后不能重复撤销。
- 仅在预定后、外部初始化前的异常处理中执行 TryCancelReservation。锁内逐一核对票据、当前池活跃 id 和索引，然后恢复旧身份；仅移除本票据新增的成员与索引，保留之前存在的历史引用。新 id 不应允许覆盖其他池已有映射。
- CreateSession 返回之后的 SetActiveCore、轮次继承和资源回调必须单独报告后处理失败，不让工具笼统声称“新会话创建失败”并诱导重试创建。是否把这些必要状态移到后台启动前属于后续行为变更，需要单独对拍。

## 故障注入入口与验收

用显式创建阶段 hook 或测试协调器注入异常，不依赖真实模型、线程调度或损坏正式 Storage。

| 注入点 | 验收 |
|---|---|
| 配置/spec 准备失败（预定前） | claim、成员、索引均未改变 |
| 票据产生后、组件初始化开始前 | 条件成立才恢复旧身份，删除新增索引；根池与子池都覆盖 |
| 撤销前其他接管已更换活跃 id | 撤销拒绝，不覆盖第三方状态 |
| newId 已映射到其他池 | 预定拒绝，不破坏已有寻址 |
| 组件已开始或会话表已发布后抛错 | 禁止简单恢复旧占用；报告准确阶段 |
| 第一个订阅成功后第二个失败 | 已记录外部发布，不能只恢复池状态 |
| AutoClaim/Bootstrap 后失败 | 不重放外部动作，不凭“尚未启动”回滚 |
| 后台排队后/compact SetActiveCore 后处理失败 | 新接管保持，旧会话释放不能取消新 claim |
| 资源 rebind 部分成功后失败 | 不把资源或 claim 假设为全部未发生 |

还需验证真实退出释放路径与仅 Listen 资源清理；已有池测试全绿不证明这些故障场景成立。本文不宣告 C12 或接管创建事务完成。

## 已实施的最小边界

预定票据已接入 compact/escalate：spec先准备，再锁内预定；compact无池继续原创建路径。CreateSession包装只接受同引擎且newId匹配的票据，准备/构造异常尝试条件撤销。RuntimeSession构造完成即封闭票据，早于外部服务与组件初始化。受控测试证明构造前失败可撤销、外部服务访问失败后不回滚，测试不启动后台。这个保守发布点不表示外部资源已成功初始化，也不提供发布后失败的清理事务；其余审计风险继续保留。
