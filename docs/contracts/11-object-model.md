# 对象模型：类 / 方法 / 属性 / 变量（11）

> 依据：`04-graph-model.md`（求解与 tick）、`10-blocks-and-wiring.md`（节点目录）。
> 本文是**最终的对象模型**，取代早期"四类块 + 拼接块"的表述。冲突时以本文为准。

---

## 1. 五个概念

| 概念 | 编程类比 | 说明 | 数量 |
|---|---|---|---|
| **激活源** | 生命周期事件（构造/启动入口） | 图"什么时候开始跑"。静态图 = 外部事件；动态图 = `clock`；作为模块被调用时 = 调用方的激活汇 | **每图恰好一个** |
| **激活汇** | 方法 | 图"做什么"。带 `t`（是否触发）与实参；对调用方是汇，对被调方是激活源 | 任意多个 |
| **数据源** | 属性（读） | 图"读什么"。激活时现场取值；作用域可为内部或导出 | 任意多个 |
| **数据汇** | 属性（写） | 图"发布什么"。不产生副作用，只把值写出去 | 任意多个 |
| **变量** | 内部存储 | 图"记住什么"。跨激活保留，属于实例；是唯一合法状态 | 任意多个 |

**取消的东西**（相对早期版本）：

- `fired` 插口 —— 每图只有一个激活源，它是否触发是恒真的，不需要插口。
- 拼接块类别 —— 状态改由**变量 + 两类图**承载；跨拍不再需要专门块。

## 2. 两种图

| | 无状态图（**静态类**） | 有状态图（**动态类**） |
|---|---|---|
| 实例 | **唯一**（进程内一个实例） | **可有多个**，各自独立 |
| 激活源 | 外部事件（频道 / 信号 / 定时 / 被调用） | `clock`（恰一个） |
| 一次激活 | 一次求解：初始除源外全未知 → 逐个求解 → 值唯一 → 清理中间态 | 一个**时钟沿**：读快照 → 同步更新 → 拍末交换 |
| 环 | 不可能（有环必然无解 ⇒ 求解无效） | 允许（每条边自动带 1 拍延迟） |
| 变量 | 该唯一实例的字段（等价单例状态） | 每个实例各自一份 |
| 失败 | 求解无效（不产生副作用） | 编译期保证初值齐全；运行时只剩模块失败 |

**共同点**：两者都是"类"，都靠"激活源 / 激活汇 / 数据源 / 数据汇 / 变量"这五个概念描述，都可以被别的图当作模块引用。

---

## 2.1 生命周期事件（与"一图一激活源"的衔接）

生命周期分阶段，但**不是给一张图多个激活源**，而是每个阶段一个独立的小类：

| 阶段 | 类 | 激活源 |
|---|---|---|
出生 | `{class}.mount` | `on.mount`（实例化后立即激活一次） |
运行 | `{class}` 本身 | `on.clock` / 外部事件 |
死亡前 | `{class}.kill` | `on.kill`（销毁前最后激活，可调用 `sink.cancelKill()` 取消本次销毁） |

规则：
- 每个类仍然**只有一个激活源**；生命周期是"多挂几个类"，不是"给一个类加多个入口"。
- 强杀（`instance.kill(force: true)` 或取消次数超阈值）**跳过** `on.kill`。
- 取消只否决本次请求，不阻止未来请求；防僵尸上限默认 3 次。

## 2.2 模块边界 = 图的粒度

**图只表达模块之间的连线，不表达模块内部。** 每个模块（如 agent 循环）自成体系、只暴露接口：

| 模块对外 | 图中表现 | 内部 |
|---|---|---|
生命周期入口 | 激活源 | 不可见、不可在图上插入 |
方法 | 激活汇（带实参与 `t`） | 实现细节 |
属性（读） | 数据源 | 内部状态不可见 |
属性（写） | 数据汇 | |
内部存储 | **不暴露**（仅模块内部变量） | |
返回 | 方法返回值 / 数据汇 | |

由此产生的四条判据：

1. **一个模块内部不允许再画图**（禁止图套图）；否则调试成本指数上升。
2. 图不表达循环、算法、错误恢复策略——这些属于模块内部时序，一旦允许图在中途插手，模块就不再"自成体系"。
3. 节点数预期 **每图 ≤ 20–30**；超过说明模块切分过细，应该合并回去。
4. 模块之间**不共享可变状态**：变量属于实例，跨模块只能读"上次提交值"。

**边界怎么切**：一个模块 = 一个明确职责 + 一段"不需要被观察、也不该被打断"的内部时序。若你发现必须在某段流程中途插入条件判断，说明它该拆成两个模块——**去改代码拆分，而不是在图上绕过**。

## 3. 调用语义：多触发 = 多个图调同一个方法

坚持"一图一个激活源"，多触发这样表达：

```
图A（被@时）──激活汇 respond(t)──┐
                                  ├─▶ 模块 respond 的激活源 ──▶ 图C
图B（信号down时）──激活汇 respond(t)─┘
```

- 激活汇属于**模块**；一次调用 = 被调图的一次激活，带新的 `traceId`，`parentTraceId` 指向调用者。
- 想表达"我觉得该回答时"，就定义一个模块（图），导出方法 `respond`；两个触发图各自接线调用它。
- 这样每个图的激活源仍然唯一，`t` 的含义也单一：**本图这次激活是否要调用这个方法**。

### 调用时序

| 被调图 | 执行 |
|---|---|
| **宏内联**（静态图，展开进调用方） | 在调用方本次求解**内**同步执行，共享同一 tick |
| **实例调用**（动态图实例 / 跨图实例） | 排队到调用方**激活结束后**执行，各自一个 trace |

## 4. 变量的语义

```csharp
VariableDecl { Name, Type, InitialValue, Mutable, Scope: Instance }
```

| 项 | 规则 |
|---|---|
读 / 写 | `read.var(name)` → 值；`write.var(name, value)` → 无副作用 |
作用域 | 变量属于**实例**：动态图每实例一份；静态图只有一个实例，因此等价单例状态 |
提交时机 | 一次激活内所有写入在**激活成功结束**时一次性提交；激活失败（求解无效/模块异常）→ 丢弃全部写入 |
动态图 | 每拍读快照、写缓冲，拍末交换（双缓冲，环合法的基础） |
持久化 | 随实例落盘；崩溃恢复为上次提交值 |
并发 | 同一实例的激活**串行**；不同实例可并行 |
导出 vs 内部 | 数据源/数据汇 = 导出作用域的"属性"；`read.var` / `write.var` = 内部作用域的"存储"。两者语义同构，只是可见性不同 |

**为什么变量能替代拼接块**：去抖/节流/计数/锁存/边沿，本质都是"变量 + 时钟"，而这两样现在都是一等概念，不需要为它们各造一个块。

---

## 5. 读取口径（保证"值唯一"不被跨图依赖打破）

| 读取场景 | 读到的值 |
|---|---|
同图内（含宏内联子图） | 当前求解中的值 |
跨图（实例 / 脉冲调用） | **上一次提交的值**（静态图 = 上次激活提交；动态图 = 上一拍） |

否则静态图的求解阶段就会依赖别的图"这次会不会改"，`值唯一` 立即失效。

## 6. 校验规则

| 检查 | 结果 |
|---|---|
| 静态图激活源数量 ≠ 1 | 报错 |
| 动态图 `clock` 数量 ≠ 1 | 报错 |
| 动态图存在未声明初值的节点 | 报错 |
| 静态图出现依赖环 | 求解期判**求解无效**（编译期另行提示） |
| 激活汇缺 `t` 输入 | 报错 |
| 变量未声明初值 / 只读变量被写 | 报错 |
| 静态图声明可变变量 | 允许，但需显式 `mutable: true` 并在 UI 标注"单例可变状态" |
| 汇块要求 `fired`、使用已废弃的 `splice.*` 类型 | 报错（概念已取消） |

## 7. 旧节点 → 新形态对照

| 旧 | 新 |
|---|---|
| `channel.watch`（带 `fired`） | 激活源 `on.message`（事件自带 `channel` 字段）+ 算子 `event.get(channel)` |
| `signal.adapter.*` | 激活源 `on.adapter.down/up/degraded/error` + 数据源 `read.adapterHealth(adapterId)` |
| `stream.email` | 激活源 `on.email(folder)` + 数据源 `read.email` |
| `timer.cron` | 激活源 `on.timer(cron)` |
| `splice.debounce` / `throttle` / `cooldown` / `counter` | **动态图**（变量：`lastAt` / `count`，时钟=消息脉冲） |
| `splice.latch` | **变量**（`Bool`） |
| `splice.edge` | **动态图**（变量：上一拍值） |
| `splice.delay(ticks)` | 动态图 + 计数变量；`delay(ms)` → 定时源 `on.timer.once` |
| `splice.wait` | 激活汇参数 `waitMs`（框架队列）+ 数据源 `read.resource(r)` |
| 汇块 `sink.session.start` | 激活汇（方法），参数含 `waitMs` |
